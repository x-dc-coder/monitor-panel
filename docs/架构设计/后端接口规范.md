# 后端接口规范（API Contract）

> 本文是 `/api/*` 全部 HTTP 接口的**权威契约**与**新增监控项的强制工作流**。
> 依据 2026-10-20 双模型交叉审查（glm-5.3 + Atria-Dawn）与治理实施定稿，
> 治理后状态：错误形态 4 套 → 1 套、response model 覆盖 15/15（除法定例外）、
> 契约测试 17 个、openapi 覆盖守卫生效。**任何接口变更以本文为准。**

## 1. 核心契约规则（R1–R7，变更接口前必读）

| 规则 | 内容 |
|---|---|
| R1 成功信封 | 所有 `/api/*` JSON 成功响应 = `{ok:true, data:T, ts}`，一律经 `app/api/__init__.py` 的 `ok()` 构造；`ts` = 响应生成时刻（epoch 秒 float） |
| R2 错误信封 | 所有错误 = `{ok:false, error:<字符串>, ts}`，HTTP 状态码不变。**error 一律字符串，禁止 dict**。实现：main.py 全局 `HTTPException` / `RequestValidationError` handler 兜底，业务代码直接 `raise HTTPException(...)` 即可 |
| R3 data.ts 语义 | 信封 `ts` = 响应时刻；`data.ts` **仅当数据本身有采集时刻语义时存在**（frp/certs/system/network 的快照 ts，可为 null），且禁止与信封 ts 同义重复（services/grm/updates 已删） |
| R4 参数命名 | 节点过滤 query 参数一律 `node`；缺省语义 = 本机（`config.NODE_ID`）；`"all"` 显式跨节点聚合**仅 /api/history 支持**（其余端点 `"all"` 按字面节点名处理）；path 参数 snake_case；时间戳字段后缀 `_ts` |
| R5 响应模型 | 每个 JSON 端点在 schemas.py 定义 `XxxData` + `Envelope[T]`，挂 `responses={200:{"model":...}}`——**只进 openapi，禁止 `response_model=` 运行时过滤**（会静默裁字段） |
| R6 类型管线 | 改接口/模型后必须：`npm run gen:types` → 提交 `types.gen.ts` → `npm run typecheck` 通过 → 才算契约闭合。types.gen.ts 入库，types.ts 高频类型 re-export |
| R7 错误处理分层 | 业务错误 = `HTTPException(status, "中文消息")`（handler 自动信封化）；参数校验缺失 = FastAPI 自动 422（handler 归一为信封）；SSO guard 401 与 `_bearer` 401 均走信封；`/api/ingest` 的 Bearer 校验保留 `WWW-Authenticate` header（handler 透传 headers） |

## 2. 端点清单（18 个，治理后状态）

| 方法/路径 | 参数 | 响应模型 | node | 备注 |
|---|---|---|---|---|
| GET /api/healthz | 无 | **平铺（法定例外，形状冻结）** | 忽略 | deploy.sh 健康检查强依赖（grep `"ok":true` + `"mode":"live\|snapshot"`），有形状冻结测试 |
| GET /auth/login・callback・logout | 无 | 302 重定向流（非 JSON 契约） | — | Casdoor SSO；callback 400 走信封 |
| GET /api/me | 无 | MeEnvelope | 忽略 | 未登录 = **401 信封**（与 guard 一致）；SSO 关闭时同样 401 |
| POST /api/ingest | body{results} | **不入 schema（故意隐藏）** | body 内 node_id | 404=未启用（不可发现设计）；401 带 WWW-Authenticate；400 unknown node = 字符串含 rejected/registered 明细 |
| GET /api/overview | ?node | OverviewEnvelope | ✅ 快照级 | 聚合视图；`updated_at` = 各区块快照最大 ts；lab 区块为 passthrough（见 §5 债务） |
| GET /api/alerts | ?limit、?unresolved_only | AlertsEnvelope | 忽略（全局事件流） | 语义如此，已文档化 |
| GET /api/devices | ?node | DevicesEnvelope | ✅ | **缺省 = 全部 tailnet 设备**（与 §5 债务 D1 一致，特例已文档化） |
| POST /api/devices/{id}/ping | path id | PingEnvelope | — | 429 限流 / 404 / 400 坏 IP / 502 采集失败；mock 分支为真实形状超集 + mock:true |
| GET /api/services | ?node | ServicesEnvelope | ✅ 缺省本机 | |
| GET /api/updates | ?provider、?node | UpdatesEnvelope | ✅ 缺省本机 | |
| GET /api/grm | ?node | GrmEnvelope | ✅ 缺省本机 | |
| GET /api/frp | ?node | FrpEnvelope | ✅ 快照级 | 无隧道回退 DB 并标 stale（>15min）；快照 ts 可 null |
| GET /api/history | metric 必填、?range、?bucket、?group、?node | HistoryEnvelope | ✅ **唯一支持 node=all** | 非法 metric/range = 400；缺 metric = 422（均信封化） |
| GET /api/system | ?node | SystemEnvelope | ✅ 快照级 | 快照缺失回退 samples |
| GET /api/certs | ?node | CertsEnvelope | ✅ 快照级 | ts 可 null |
| GET /api/network | ?node | NetworkEnvelope | ✅ 快照级 | ts 可 null |

## 3. 例外清单（法定脱离信封者）

1. **GET /api/healthz**：平铺 `{ok, uptime, version, mock, mode, node, collectors}`——部署管线契约（deploy.sh 双重 grep 校验 + 形状冻结测试），**永不信封化**。
2. **/auth/*** 三端点：浏览器 302 重定向流（Casdoor post_logout 约束），非 JSON 契约。
3. **POST /api/ingest**：`include_in_schema=False`（接口不可发现的安全设计）+ 404-on-disabled 语义，均为有意设计。

## 4. 新增监控项 API-first 工作流（强制检查单）

> 用户决策（2026-10-20）：**每新增一个监控项，必须先调通并验证后端接口的数据准确性，再做前端。** 下列步骤按序执行，前置未通过不得进入前端开发：

1. **白名单登记**：`app/constants.py` 的 `GROUP_METRICS` 登记 base 指标名——漏了会出现"数据入库但查不到"的幽灵问题（db.insert_samples 按白名单静默丢弃）。
2. **契约先行**：schemas.py 定义 `XxxData` 模型 + `Envelope[T]`，挂路由 `responses={200:...}`。
3. **契约测试先行（红）**：tests/ 写该端点契约测试（信封三字段、关键字段类型、空数据形态、`?node=` 过滤），先跑红。
4. **实现转绿**：实现 collector + 聚合 handler + 端点（ok() 信封），契约测试转绿。
5. **数据准确性验证（核心）**：mock 模式全测后，起 live 服务用 curl 对照**真实数据源**人工核对值（不是只看 200）；用 sqlite 复核 samples 入库的名称与数值。
6. **类型闭环**：`npm run gen:types` → 提交 types.gen.ts → types.ts 加 re-export → `npm run typecheck` 通过。**此时前端方可动手。**
7. **回归门禁**：全量 pytest（132+）零回归 + `npm run test` + 构建通过。

## 5. 已知债务（治理边界外，按序偿还）

| # | 债务 | 说明 | 偿还方式 |
|---|---|---|---|
| D1 | devices/updates 缺省 node 语义 | 二者缺省=全部节点（表 8 行含全部 tailnet 设备），其余端点缺省=本机——语义分裂但是有意设计（设备表即 tailnet 清单） | 文档化为特例；若改需产品决策 |
| D2 | lab 区块 camelCase passthrough | lab-monitor 上报字段原样透传（runId/cpuPct 等），与全仓 snake_case 不一致 | lab-monitor 开发时在 ingest 层归一化，schema 放宽声明 |
| D3 | 手写 PingResult 与 gen 的 PingData 并存 | views/devices.ts 用手写类型，types.gen 另有 PingData | views 改用 gen 类型后删手写版 |
| D4 | 警告级告警的历史积压 | sso 证书续期前（<30 天 CRIT）的历史告警在告警表 | 随 resolve 机制自然消退 |
| D5 | 错误响应无统一 schema 声明 | openapi 只守卫 200 具名模型，401/404 等错误响应无 $ref | 后续在 schemas.py 加 ErrorEnvelope 并挂 responses={...,"4XX":...} |
| D6 | 前端 api.ts 的 detail 兼容分支 | `detail || j.error` 双兼容是为迁移期保留 | 错误格式稳定一个版本后删除 detail 分支 |

## 2. 双模型一致的高置信问题（详单）

### P0-1 ｜ SSO 会话密钥默认值 + 启动校验缺口

- 证据：`SESSION_SECRET_KEY = _env("MONITOR_SESSION_SECRET", "monitor-panel-session-secret-key-change-me")`；
  `validate_config()` 只检查 `FRPS_PASS`/`LEGACY_TOKEN`，对会话密钥零校验；
  SessionMiddleware 用它签名无服务端状态的 `monitor_session` cookie。
- Atria PoC：不设该 env 启动后，用公开默认密钥自签 `{"user":{...}}` cookie，
  `/api/overview`、`/api/alerts`、`/api/devices` 全部 200（无 cookie 时 401 正常拦截）。
- 影响：生产若漏配 `MONITOR_SESSION_SECRET`，SSO 形同虚设，设备清单/隧道/证书/台账
  （含内网 IP、端口分布、证书 SAN）全部暴露。这正是 issue #1 "fail-fast 防配置静默"
  想防的问题类别，但漏了这一项；`.env.example` 也没有该变量（README 宣称覆盖全部 68 个变量）。
- 服务器侧已核实（2026-10-20）：生产 `/opt/monitor-panel/env` 使用自定义密钥——用默认密钥伪造
  的会话 cookie 请求 `/api/overview` 实测 401，P0-1 线上未暴露。但**生产 nginx 已无全站
  Basic Auth**（活动配置 `/etc/nginx/sites-enabled/monitor` 仅 ACME 与 `/api/ingest` 两处
  `auth_basic off`，`location /` 无任何 auth_basic），SSO 会话是唯一门禁——本缺口修复前
  没有第二道栅栏。仓库脚本 `setup_nginx_cert.sh` 若重跑会重新引入全站 Basic Auth
  （脚本与现网漂移，见 P2 第 11 条）。**fail-fast 缺口在任何环境下都成立**。
- 建议：`validate_config()` 增加——SSO 启用且 `CASDOOR_CLIENT_ID` 非空时，
  secret 等于默认值或长度不足即拒启；`.env.example` 补该变量；生产确认并更换随机密钥。

### P1-2 ｜ ingest 空 token（降级：fail-fast 缺口）

- 证据：`expected = f"Bearer {config.INGEST_TOKEN}"`；token 为空时对 `Authorization: Bearer `
  （含尾随空格）`hmac.compare_digest` 恒真。`validate_config()` 对 "INGEST_ENABLED=1 而
  token 为空" 的半配置放行。
- 实测：TestClient 层 `Bearer ` 返回 200；真实 uvicorn（h11 规范化头部、剥离尾部空白）
  下同请求返回 **401**。生产链路 nginx → uvicorn，故当前不可利用。
- 服务器侧已核实（2026-10-20）：生产 **`INGEST_ENABLED=1` 且 token 非空**——空 token 与无 token
  请求 `/api/ingest` 均实测 401（nginx 公网与 127.0.0.1 直连双路径确认）。半配置现状不存在；
  但"ingest 已启用"意味着本条与 P1-6（快照覆盖）从"接入前修"升级为**现状暴露面**
  （见架构审查报告 §5）。
- 建议：`validate_config()` 增加"INGEST_ENABLED 时 INGEST_TOKEN 必填（建议 ≥24 字符）"；
  `_bearer` 对空 expected 直接 401。

### P1-3 ｜ update_items 永不 prune（僵尸仓库）

- 证据：`_on_grm` 调 `db.upsert_update_items(result.node_id, items)`（prune 缺省 False）；
  同函数 `db.upsert_grm_repos(...)` 默认 prune=True（语义正确）；且 `if items:` 为空时
  连 upsert 都跳过。Atria 实测：grm 数据 3 仓库删到 1，`grm_repos`=1 而 `update_items`=3。
- 影响：grm 侧删除仓库后 `/api/grm` 正确消失、`/api/updates` 永久残留，且 `is_new`
  冻结在历史值；前端 releases.ts 优先消费 updatesData，用户看到删不掉的僵尸卡片。
- 建议：非降级轮次 `prune=True`；空列表语义与降级语义对齐（degraded 不清空）。

### P1-4 ｜ /api/updates 与 /api/grm 字段漂移

- 证据：`rows_to_items` 不产出 `is_pinned`/`readme_summary`；`/api/grm` 全部提供。
  前端 `updateItemToCard` 读 `item.is_pinned` 恒 undefined；`grmRepoToCard` 富路径只在
  updates 为空的回退分支生效；而 `_on_grm` 每轮双写使 updates 恒非空。
- 影响：置顶排序/📌徽标/readme 摘要在主路径全部静默失效。
- 建议：`/api/updates` 从 grm 行透传 `is_pinned` 与 `summary`（readme_summary/recent_commits
  归一），或前端按 `item_key` 回退合并。

### P1-5 ｜ services open 路径覆盖 manual 行（Atria 独有）

- 证据：采集器开放分支硬编码 `"source": "auto"` 且行内无 `enabled` 键（services.py 开放路径）；
  `upsert_services` 的 DO UPDATE 无条件 `source=excluded.source, enabled=excluded.enabled`
  （enabled 落到默认值 1）。`_prune_services` 只跳过 `source=="manual"` 的行。
- Atria 实测：manual 行（enabled=0）经一轮开放端口扫描后变 `source=auto enabled=1`；
  之后端口移出约定区即可被 prune 删除并 resolve 告警——"manual 永不删"承诺失效。
- 建议：upsert 分支改 `CASE WHEN services.source='manual' THEN 'manual' ELSE excluded.source END`
  （enabled 同理），或采集器 open 路径透传 prev 值（与 closed 路径一致）。

### P1-6 ｜ 认证中间件后缀放行过宽

- 证据：`path.endswith((".js", ".css", ..., ".map"))` 对所有路径生效；同函数注释明确写着
  "收紧为面板实际产出的清单——任意路径后缀放行会让未认证者读到脚本"，代码与注释矛盾。
- 影响：当前无直接泄露端点（静态资产本就公开），但属结构性弱点，未来 `.map` 落盘即自动公开。
- 建议：改精确前缀白名单，删 endswith 分支；构建侧继续禁出 sourcemap。

### P1-7 ｜ latest 快照缺 node 维度（多节点核心阻塞）

- 证据：`self.latest` 注释即"group → 最新 payload"，写入不看 node_id；ingest 接受任意 node_id。
- 影响：cloud-2（或任何 ingest 上报方）上报 `system`/`ts_latency` 等 group 即覆盖本地快照，
  全部只读 API 呈现错乱数据。`INGEST_ENABLED=false` 期间潜伏（生产实际值待确认）。
- 建议：latest 键改 `(node_id, group)`，读侧加节点过滤；配套 ingest node 注册校验
  （见架构审查报告修补项 M1/M3）。

### P1-8 ｜ 前端轮询无在飞防护

- 证据：10 路 `setInterval` 直接 `S.x = await api(...)`；全仓 web/src 无 AbortController/signal
  使用，`api()` 的 fetch 无超时。
- 影响：后端抖动时旧响应后到覆盖新数据、请求堆积放大负载。
- 建议：每路轮询加在飞标志 + fetch 超时/AbortSignal。

## 3. P2 详单（摘要）

1. **aggregator.py:38 优先级 bug**（glm）：`(m[0], m[1], m[2] or ts if len(m) > 2 else ts)`
   解析为 `m[2] or (...)`，2 元组形态 IndexError 后被外层 except 吞掉、整组静默失败。
   当前唯一调用方恒传 3 元组，属潜伏。
2. **scheduler.stop() 无效收尾**（双方）：gather 睡眠 0 秒不等待任何任务；main.py 随即
   `run_task.cancel()` 硬取消在途采集（含 db 写）。建议保存运行中 Task 并 `wait(timeout=5)`。
3. **`_last_manual_ping` 只增不减**（glm）：模块级 dict 无淘汰，量级极小。
4. **ingest 链路同步 SQLite 阻塞事件循环**（glm）：比照 `cleanup_async` 用 `to_thread`。
5. **证书告警 `days=None` TypeError**（glm，潜伏）：首分支 status=CRIT 可在 days 为 None 时
   走到 `{days:.0f}` 格式化。
6. **/api/system 回退死代码**（Atria）：`agg.latest_ts and agg.latest_ts.get(...)` 在空表时
   返回 `{}` 而非 None，`if latest is None` 恒 False；重启后首轮采集前前端显示空值。
   修复判空为 `if not latest:`。
7. **KPI sparkline 误用**（Atria）：CERTS/PROBES 卡片传 sparkKey `"cpu"`，画的是 CPU 曲线。
   不传 spark 或定义对应指标。
8. **certs gather 无 return_exceptions**（Atria）：`_probe_tls` 只捕获部分 SSL 异常，
   其余异常废掉整轮（certs 周期 3600s，一次异常=1 小时无证书数据）。
9. **SSH 协议识别失效**（Atria）：HTTP 预读消费 banner 后 `head[:24]` 无 "HTTP/"，
   protocol 恒 "tcp"；二次 banner 读只能超时，无响应端口双倍超时（2s+1s）。
10. **`new URL` 未保护**（Atria）：配置 path 含非法字符时渲染抛 TypeError 被 poll 静默吞掉。
11. **nginx 脚本与现网漂移**（Atria 发现，2026-10-20 现网核实后重述）：现网活动配置已移除
    全站 Basic Auth（SSO 唯一门禁）；`setup_nginx_cert.sh` 仍写有 443 全站 `auth_basic`——
    重跑脚本会重新引入 Basic Auth，SSO 跳转前先弹窗且安全形态回退。脚本需按现网重写。
12. **deploy 链路三处**（Atria）：`set -euo pipefail` 下回滚分支 `ls` 空结果直接静默退出；
    `deploy/sudoers.monitor` 模板缺 `monitor-deploy-ctl` 规则（服务器侧已另行安装，仓库模板漂移）；
    `backup-db.service` ExecStart 指向 releases 外固定路径，deploy 不更新它。
13. **杂项**（Atria）：`db.touch_node()` 无调用方（节点心跳未通电）；foot-node 只显示
    `nodes[0]`；`.env.example` 缺 `MONITOR_SESSION_SECRET`；devices.ts 渲染末尾疑似多余
    `</div>`（低置信，浏览器容错，待验证）。

另：Atria 对时间处理专项核查结论为**无问题**（tailscale ISO/Go 零值解析、db 全链路 epoch 秒均正确），
glm 提出的时区疑点经核实排除。

## 4. 测试盲区（两模型合并）

- **会话安全**：无默认密钥 fail-fast 用例、无"伪造签名 cookie 必须被拒"用例（直接掩盖 P0-1）。
- **updates 链路**：`/api/updates` 无 is_pinned/summary 字段断言；prune 生产路径无用例
  （现有 roundtrip 测试直连 db 且显式传 prune=True，掩盖 P1-3/P1-4）。
- **服务台账**：manual 行被 open 路径覆盖无用例（现有 roundtrip 的 manual 行不在扫描集合内，
  掩盖 P1-5）；SSH banner 真实探测路径无用例。
- **ingest**：无"远端上报覆盖本地 latest 快照"场景；无空 token 用例；无 node 白名单用例。
- **auth 中间件**：无 `/api/foo.js` 后缀绕过边界用例。
- **certs 采集编排**：`_run_real` 的 TLS/回退/并发编排无用例（仅 `_parse_der` 自签单测）。
- **/api/system 回退**、**/api/history 多节点混合**：均无用例。
- **scheduler 周期语义**：仅 2 用例，未锁"实际周期 ≈ interval"（历史线上事故）。
- **运维脚本**：deploy.sh（含 --rollback、健康检查失败路径）、backup-db.sh、fetch_snapshot* 全部无测试。
- **前端**：仅 table.test.ts；轮询竞态、api.ts、releases 回退逻辑、12 视图渲染均无单测。

## 5. 修复优先级建议

1. **立即**（低成本、防半配置上线）：P0-1 session secret 校验 + `.env.example` 补齐；
   P1-2 ingest token 校验。同属 `validate_config()` fail-fast 补全，约 20 行 + 用例。
2. **下一次迭代**：P1-3 prune 与 P1-4 字段补齐（updates 链路一并修 + 补断言）；
   P1-5 manual 行不变量（一条 CASE 语句 + 用例）；P1-6 后缀白名单收紧；
   P2-6/P2-7/P2-8 三个一行级修复（system 判空、KPI spark、certs gather）。
3. **cloud-2 接入前必须**：P1-7 latest 快照 node 维度（与架构审查报告修补项 M1/M2/M3 打包实施）。
4. **顺手清理**：P2 其余项 + 与上述修复配套的测试盲区用例。

## 6. 服务器侧确认结果（2026-10-20 已核实）

| 事项 | 结论 | 方法 |
|---|---|---|
| `MONITOR_SESSION_SECRET` | 生产为自定义值，P0-1 线上未暴露（fail-fast 缺口仍在） | 默认密钥伪造 cookie 请求 `/api/overview` 实测 401 |
| `INGEST_ENABLED` / token | **已启用**且 token 非空；空/无 token 均 401 | 空 POST `/api/ingest` 探针（公网 + 127.0.0.1 双路径） |
| nginx Basic Auth | **现网已移除全站 Basic Auth**，SSO 唯一门禁；`setup_nginx_cert.sh` 与现网漂移 | 读活动配置 `/etc/nginx/sites-enabled/monitor` |
| `update_items` 残留 | 当前 17 行 = `grm_repos` 17 行，尚未实际分叉；P1-3 为潜伏 | 只读 SQL（只读打开生产库） |
| 多节点现状 | samples 仅 `cloud-1`（400 万行）；`monitor_nodes` 仅 cloud-1，lab 转发器未注册 | 只读 SQL |
| lab 上报活跃度 | 近 30 天 samples 零 `lab_monitor` 行（该组在白名单内，若上报带指标必入库）+ journald 保留期（约 36h）内零成功 ingest 日志 → 近 30 天无带指标的成功上报；**当前是否活跃未能确认** | 只读 SQL + journalctl |
| 生产健康度 | release 20261002-034000，mode=live，采集器 0 errors，uptime 18.6 天；terraform 巡检：磁盘 30.7%、内存 43.2%、frps/nginx/casdoor/headscale/tailscaled 全部 active | `/api/healthz` + linux-ops terraform audit |

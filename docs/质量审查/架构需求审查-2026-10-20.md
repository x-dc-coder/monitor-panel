# 架构需求符合度交叉审查报告（2026-10-20）

> 审查方式：glm-5.3 与 Atria-Dawn 两个独立模型按同一任务书做"需求→架构"只读评审，
> 主会话合并比对并核实关键证据。产品需求基线（用户给出）：
> ① 聚合多源数据（服务器运维、Tailscale 网关、各服务站点探测等）；
> ② 支持其他服务灵活接入（releases 面板为首个非监控源）；
> ③ 多节点扩展（cloud-2 经 /api/ingest 上报，当前 INGEST_ENABLED 默认 false）。
> 代码级伴生发现（认证、prune、manual 行覆盖等）见《交叉审查报告-2026-10-20》。

## 1. 结论速览

**总评（双方一致）**：这是"监控核心需求高质量交付、扩展性宣称超前于实现"的架构。
多源聚合（R1）与全部隐含运维需求完成度高且有文档/测试/CI 闭环；
服务接入（R2）与多节点（R3）均为"首个特例成功 + 抽象口留了但没接电"。

| 需求 | 判定 | 分歧 |
|---|---|---|
| R1 聚合多源数据 | **已满足** | 无（Atria 补充：当前"聚合"是快照拼接，无统一数据模型，够用） |
| R2 其他服务灵活接入 | **部分满足** | 无（glm 估新源接入改 5-6 处，Atria 数出 14+ 处，取后者明细） |
| R3 多节点扩展 | **部分满足（语义断链）** | 表述差异：glm"不满足"、Atria"部分满足"，实质一致——预留兑现、语义未完成 |
| 隐含·告警 | 已满足（无外发通知通道，二期项） | 无 |
| 隐含·历史趋势 | 单节点满足（多节点会跨节点混算） | 无 |
| 隐含·移动端 | 已满足 | 无 |
| 隐含·认证 | 已满足（SSO 超出 v1.1 设计；漏洞见交叉审查 P0-1） | 无 |
| 隐含·部署运维 | 已满足 | 无 |

## 2. 逐需求符合度结论

**R1 多源聚合：满足。** 8 个采集器覆盖需求全部三类来源，统一走
`CollectorResult → Aggregator.ingest() → samples 入库 + 内存快照 + _on_<group> 阈值/告警` 管道
（`app/collectors/__init__.py` 注册表、`app/services/aggregator.py` 派发）。
站点 http 探测由 services 台账承担，证书已演进为 SNI 主动探测。
单体单 worker 是有论证的设计决策（docs/架构设计/技术方案.md §2.1），当前数据量（约 5.8 万行/天）下正确。

**R2 服务灵活接入：部分满足。** grm 作为首个非监控源全链跑通（docs/架构设计/release-monitor.md 有契约、降级语义、测试），
前端也有 `registerUpdateProvider` 渲染注册。但通用化未兑现：
- `UpdateProvider.fetch()` 与 `fetch_all()` **无任何生产调用方**（PROVIDERS 注册表只被
  `/api/updates` 拿来列名单）——抽象口留了，管道没接；grm 实际靠 collector + aggregator
  旁路内联双写（`_on_grm`）。
- 新增一个数据源要改 14+ 处：constants 白名单 → collector 类 → 注册表 → `_on_` handler →
  db 三件套 → api 路由 → main 挂载 → schemas → types.gen → 前端 view → ViewId → 轮询注册 →
  state → 导航 → 文档。编译期保障仅 ViewId 联合与 types.gen 漂移检查两处。

**R3 多节点：部分满足，语义系统性断链。** "预留"层兑现得好：7 张表全带 node_id、
ingest 契约/认证/nginx 豁免/404 不可发现均有测试（docs/运维手册/cloud2-ingest-runbook.md）。但"语义"层断链：
内存快照无节点维度（下游 API 全部跟着错）、history 无 node 过滤（跨节点混算平均）、
节点注册表/心跳未通电（`touch_node` 死代码）、ingest 不校验 node 注册且单 token 无 per-node
绑定、前端零节点维度（foot-node 只显 `nodes[0]`）。docs/运维手册/cloud2-ingest-runbook.md 所述"同仓库轻量 agent"在仓库中
不存在。当前定位宜更准确表述为"单节点面板 + 远端上报半通道"。

## 3. 共识架构问题（按影响排序）

| # | 问题 | 证据 | 一致性 |
|---|---|---|---|
| A1 | **latest 快照缺 node 维度**：远端上报同 group 即覆盖本地快照，全部只读 API 呈现错乱数据；R3 的核心阻塞 | `aggregator.py:22,43-45` | 双方一致（交叉审查 P1-7 为其代码级条目） |
| A2 | **/api/history 无 node_id 过滤**：多节点同指标跨节点 AVG，趋势语义错误；索引不含 node_id | `db.py` query_history、`api/history.py` | 双方一致 |
| A3 | **节点注册表/心跳未通电**：`db.touch_node()` 无调用方；ingest 接受未注册 node_id（token 持有者可伪造 cloud-1 覆盖快照）；单 token 无 per-node 绑定与吊销；foot-node 只显 nodes[0] | `db.py:241`、`api/ingest.py`、`main.ts:43-44` | Atria（主会话核实属实） |
| A4 | **UpdateProvider 与 collector 体系割裂且未接电**：`fetch()`/`fetch_all()` 死代码；两套注册表、两套入库、两套前端注册 | `collectors/updates/__init__.py`、`aggregator.py:_on_grm` | 双方一致 |
| A5 | **grm 双写不一致**：grm_repos prune=True、update_items 缺省 False；`/api/updates` degraded 硬编码读 `latest["grm"]` | `aggregator.py:326-337`、`api/updates.py:24` | 双方一致（交叉审查 P1-3） |
| A6 | **新增数据源改动面 14+ 处**，无注册表可查，`_on_<group>` 命名约定派发且无启动期校验（漏写 handler 静默降级为仅 samples 落库）；handler 内混杂快照表写入/阈值/告警/派生指标四种职责 | `aggregator.py:49-59` | 双方一致（Atria 给出明细清单） |
| A7 | **存储生命周期碎片化**：samples 30d retention（cleanup）、grm prune 在 upsert 参数、services 生命周期在 aggregator、update_items 无 prune 无保留期；高 churn 源接入无机制可复用 | `db.py`、`config.py:204` | 双方一致 |
| A8 | **ingest 契约过宽**：任意 node_id/group 接受、无节点白名单（samples 级有 metric 白名单 `is_valid_metric`，payload 级无校验） | `api/ingest.py`、`db.insert_samples` | 双方一致（glm 疑点经核实：metric 白名单存在，payload/node 级缺失） |
| A9 | **单 worker + 单 SQLite + 内存快照是结构性天花板**：当前量级下不算缺陷，列出备查 | docs/架构设计/技术方案.md §2.1 评估 | 双方一致（当前无需动） |
| A10 | **lab_monitor 是"用 ingest 通道做本地扩展"的事实特例**（已现网核实）：仓库内无 lab collector/handler，纯靠 dc-desktop 转发器经 /api/ingest 上报；生产 `INGEST_ENABLED=1`（空 POST 实测 401 非 404）——ingest 事实上已是开放的第三方源通道，A1 快照覆盖风险属现状暴露面；`monitor_nodes` 无 lab 节点注册，近 30 天 samples 零 `lab_monitor` 行（转发器休眠或仅 payload） | 401 探针 + 只读 SQL + 白名单核对 | 双方一致 + 主会话现网核实 |
| A11 | **前端视图注册好但数据轮询中心化**：新源要同时改 view + state 两处，与 registerUpdateProvider 的解耦意图不一致 | `main.ts`、`state.ts` | glm |

## 4. 架构调整建议（三档）

### 4.1 保持现状——动它们是过度设计（双方一致清单）

单体 FastAPI + 单 worker + 自研调度器（overrun/jitter/单调时钟）；SQLite WAL + 批量事务 +
每小时清理；`{ok,data,ts}` 信封 + 只读 API + openapi→types.gen 漂移门禁；降级语义
（degraded 不清快照）三处复用的稳定先例；安全底子（sanitize/sudoers/env 单一权威源/
fail-fast/三层认证）；前端视图注册 + hash 路由 + 分层轮询 + 响应式；告警冷却去重
（1199 条误报治理成果，勿重写）；快照表 + node_id 主键的建模方式；轮询（10s/30s）而非
SSE/WebSocket（与采集周期匹配）。

### 4.2 低成本修补——第二个源或 cloud-2 接入之前做

| # | 建议 | 依据 | 代价/风险 |
|---|---|---|---|
| M1 | `latest`/`latest_ts` 键改 `(node_id, group)`，各读侧 API 加 `node` 参数（默认本机） | A1/R3 | 内存结构 + 读侧改造 + 单测同步；约半天，低风险 |
| M2 | `query_history` + `/api/history` 加 node_id 过滤 | A2/I2 | SQL + 索引评估；默认行为保持兼容 |
| M3 | ingest 调 `touch_node` 心跳 + 校验 node_id 已注册（未知 400）；评估 per-node token | A3/R3 安全 | 1 文件 + 更新 docs/运维手册/cloud2-ingest-runbook.md |
| M4 | `_on_grm` 的 update_items 改 `prune=True`；`/api/updates` degraded 去硬编码 | A5/R2 | 2 处，与交叉审查 P1-3 同一修复 |
| M5 | 前端 foot-node 展示全部节点 + last_seen 失联标色 | A3/R3 | `main.ts` 少量 + CSS |
| M6 | 明确 lab_monitor 归宿：补 collector 或文档化"ingest 为第三方源通道"并隔离 group 命名空间 | A10/R2 | 文档 + 命名，不改行为 |
| M7 | 启动期断言：每个注册 collector 的 group 都有 `_on_` handler 或显式声明"仅 samples" | A6 | 消掉静默降级 |
| M8 | PROVIDERS 死路径二选一：删掉注册表诚实面对内联现实，或把 `_on_grm` 双写改走 `GrmProvider.fetch()` 消灭双路径 | A4 | 避免假插件口持续空心化 |

### 4.3 结构性调整——明确触发条件后再做（现在做即过度设计）

触发条件（满足其一）：第三个非监控源确认要接；cloud-2 正式上线排期确定。

1. **统一 DataSource 注册协议**：把 UpdateProvider 泛化为数据源插件契约
   `{collector, storage(upsert/prune/retention), api 路由, 前端注册键}`，aggregator 退化为分发器。
   先接通 `fetch()` 调度或删死代码；**新源走新协议，旧 8 源不迁移**（重构全量迁移的风险
   大于收益，且会回归生产告警语义）。
2. **每源存储生命周期声明化**：provider 契约携带 prune/retention 策略字段（A7），复用
   cleanup 与 services 两条既有先例。
3. **前端导航运行时注册**：`/api/sources` 驱动导航与轮询（保留 ViewId 联合类型兜底编译期检查）。
4. **多节点完整语义**：overview 节点化 + 前端节点选择器 + samples 索引含 node_id +
   docs/运维手册/cloud2-ingest-runbook.md 承诺的轻量 agent 实现。

## 5. 服务器侧确认结果（2026-10-20 terraform 巡检 + 行为探针）

1. **`INGEST_ENABLED`：生产已启用**（空 POST `/api/ingest` 实测 401，非 404），token 已配置
   （空/无 token 均 401）→ **M1（快照 node 维度）与 M3（节点注册校验）从"cloud-2 接入前"
   提前为建议尽快**：ingest 通道现已开放，任何持 token 方可覆盖 `latest[group]` 快照。
2. lab 上报细节：`lab_monitor` 组在指标白名单内（带指标上报必入库），但近 30 天 samples 零
   `lab_monitor` 行、`monitor_nodes` 无 lab 节点——转发器近期休眠或仅上报 payload；
   journald 保留仅约 36h，无法回溯最后成功上报时间。**剩余未知**：转发器当前是否活跃、
   其 node_id 取值（需在 dc-desktop 侧或面板现场确认）。
3. `MONITOR_SESSION_SECRET`：生产为自定义值（默认密钥伪造 cookie 实测 401），安全底子在位；
   生产 nginx 已无全站 Basic Auth，SSO 是唯一门禁（fail-fast 缺口价值上升）。
4. `update_items` 残留：17 行 = `grm_repos` 17 行，A5 尚未实际发生（潜伏）。
5. 8899 旧面板公网暴露：本次未复验（活动 monitor 配置无 8899 反代；aliyun frps 侧暴露面待查，
   仍列开放项）。

## 0. 设计目标与约束

**目标**：在 cloud（124.221.190.237，腾讯云 Ubuntu 22.04，ssh 别名 dc-sy）上部署 `monitor.dc-sy.cn`，整合 **frp 隧道监控 + tailscale 设备/连接质量监控 + 云服务器健康**，并为"第二个云服务器兜底 / 双公网 IP"预留扩展位。

**已确认环境事实**（2026-08-15 实测）：

| 设施 | 现状 |
|---|---|
| nginx | `dc-sy.cn`（→ 127.0.0.1:8899 + /cam/ → 20002）、`headscale.dc-sy.cn`（→ 127.0.0.1:8080，WebSocket 升级）两个站点 |
| frps | `/etc/frp/frps.toml`，bind 7000，dashboard `127.0.0.1:7500`（admin/basic auth），allowPorts 20000–20099 |
| 现有监控面板 | FastAPI + uvicorn `:8899`（**注意：绑定 0.0.0.0，公网可直连，`GET /` 无鉴权** — 既有风险，见 §8 E2），端点：`POST /api/report`、`GET /api/status`（含 **latency_ms / packet_loss_percent**，t1 已实测）、`GET /api/history/{id}`（上限 14 天/500 点）、`POST /api/power/*`、`GET /`；SQLite + asyncio + echarts |
| headscale | 控制面 `127.0.0.1:8080`，metrics `127.0.0.1:9090`，grpc `127.0.0.1:50443`，内嵌 DERP region 999（STUN 3478），前缀 100.64.0.0/10；服务以专用用户 `headscale` 运行；`tailscaled.sock` 权限 **666**（普通用户可连 socket，CLI 是否免 sudo 以实测为准） |
| tailscale | 4 台设备 100.64.0.1–4 |
| DNS | **dc-sy.cn 的 NS = dns31/32.hichina.com（阿里云 hichina，实测确认）** → DNS-01 挑战必须走阿里云 API；**ICP 备案状态未知（需向用户确认）** |

1. 端口避开：22/53/80/139/443/445/7000/7500/8080/8899/9090/20000-20002（及 3478 STUN、50443 grpc、3080 本地 dsh）。新面板端口 **8898**，仅绑 127.0.0.1。
2. 不得破坏现有生产服务；采集端契约（8899 agent 上报协议）是不可变基线。
3. 数据源细节以研究员 t1 报告为准（本版已按其 A/B 节实测校准 frps 端点与 8899 字段）。

## 2. 技术选型

### 2.1 后端：Python FastAPI 单服务 + uvicorn 单 worker ✅

- 与 8899 同栈（FastAPI + uvicorn + SQLite + asyncio），运维心智统一。
- **单 worker 论证**：采集为 I/O 密集，asyncio 单进程足够；多 worker 会导致采集重复执行 + SQLite 写竞争 + 内存快照不一致。
- **单 worker 下的强制规范（评审 B 补充）**：
  - 所有 collector **必须 async**，且每步操作强制 timeout（`asyncio.wait_for`，默认 10s/步，可配）。
  - 同步阻塞调用（psutil 磁盘扫描等 >50ms 的）走 `asyncio.to_thread`，防拖慢全部 API 请求。

### 2.2 调度：自研轻量 asyncio 调度器 ✅（vs APScheduler）

| 方案 | 结论 |
|---|---|
| asyncio 后台任务 + 最小调度器（~50 行：最小堆按 next_run 排序，`asyncio.sleep(next_deadline)` 驱动） | ✅ 采纳：全部"间隔执行"语义，零额外依赖，与 8899 风格一致 |
| APScheduler | ✗ 杀鸡用牛刀 |

**调度器健壮性（评审 E13）**：
- **overrun 跳过不追跑**：本轮未完成则跳过下一轮（记录 skipped 计数），不堆积。
- **jitter 防齐射**：每轮间隔加 ±10% 随机抖动，避免多采集器同拍齐射。
- **单调时钟**：调度用 `time.monotonic()`，不受系统时间跳变影响。
- 每个 collector 独立 try/except（强制规范），单个失败不影响其他。

### 2.3 前端：单 HTML + 原生 JS + Chart.js（vendored，附带 LICENSE）✅

- 免构建链；Chart.js ~200KB vendored 本地（**同时 commit MIT LICENSE 文件**，评审 B 补充），出站异常时面板仍可用。
- 实时刷新：前端轮询 5–10s（匹配 30s 采集节奏，免 nginx 长连接配置）；SSE 列为可选增强，MVP 不做。

### 2.4 数据存储：SQLite（WAL）✅

- 与 8899 同栈；数据量小（30s × ~20 指标 ≈ 5.8 万行/天，30 天 ≈ 170 万行带索引无压力）。
- **连接 PRAGMA（评审 E12 补充）**：`journal_mode=WAL` + `synchronous=NORMAL` + `busy_timeout=5000`。
- **保留窗口与清理**：samples 30 天（可配）；每小时 `DELETE ... WHERE ts < cutoff` + `wal_checkpoint(TRUNCATE)`（低频低竞争）；alerts 90 天。
- 写入批量：每轮采集结果合并为一次事务。

### 2.5 部署：nginx 反代 + **双通道证书签发** + systemd ✅（v1.1 核心修订）

**证书签发策略（🔴 评审 C1 阻塞项，v1.1 修订）**：

> 背景：腾讯云对**未 ICP 备案域名**的 80 端口投放 webblock 拦截页，ACME HTTP-01 挑战会被劫持 → 签发失败。headscale 部署时曾实测被拦，被迫改 DNS-01。monitor.dc-sy.cn 为新子域，**极可能同样被拦**——HTTP-01 假设不能默认成立。

- **双通道签发**：`setup_nginx_cert.sh --issuance http|dns`。
  - **HTTP 通道**：`certbot --nginx -d monitor.dc-sy.cn`（HTTP-01）。适用于已备案/未被 webblock 的场景，零额外凭据。
  - **DNS 通道**（推荐兜底）：**acme.sh `dns_ali` 插件 + 阿里云 RAM AccessKey**。理由：**dc-sy.cn NS 实测在阿里云 hichina**，DNS-01 需在阿里云 DNS 区域加 TXT 记录，阿里云 API 是唯一匹配通道；且 headscale 已有"阿里云 AK 走 DNS-01"的现成经验可复用。需用户提供阿里云 RAM 子账号 AK（**仅授权 DNS 解析记录读写**，如 `AliyunDNSFullAccess` 或更小自定义策略），配 `Ali_Key`/`Ali_Secret` 环境变量。备选 certbot-dns-aliyun（同凭据，二选一；推荐 acme.sh：无需 pip 插件、续期 cron 一条命令）。
  - ~~DNS-01 走 DNSPod dns_tencent/dns_dp~~：**不适用**——域名 NS 不在腾讯云/DNSPod，除非将子域 NS 单独委托（复杂度高，不推荐）。
- **预检 8a（部署步骤 8 之前强制）**：外部网络（无代理视角）执行 `curl -sI --max-time 10 http://monitor.dc-sy.cn/.well-known/acme-challenge/probe`：
  - 返回 404/200（nginx 正常响应）→ HTTP-01 可通行，走 http 通道；
  - 返回 302/30x 到 `webblock.tencentyun.com` / qcloud 拦截页 → 被拦截，走 dns 通道；
  - 同时**向用户确认 dc-sy.cn 是否已 ICP 备案**（已备案则 HTTP-01 基本可通行）。
- **续期 hook 与签发方式一致**（评审 C1 要求）：
  - http 通道：certbot 自带 systemd timer 自动续期（已有）。
  - dns 通道：acme.sh `--cron` 自动续期天然复用同一 Ali_Key/Ali_Secret；凭据文件权限 600 且不入 git。
- **Basic Auth 默认开启（评审 C2，v1.1）**：nginx 层 Basic Auth 从"可选"改为**默认开、可关**（个人面板防扫描，成本一行 htpasswd）。

### 3.3 模块职责

| 模块 | 职责 | 关键点 |
|---|---|---|
| **collectors** | 每源一采集器，产出规范化 `CollectorResult` | async 强制 + 每步超时；**统一 `sanitize()` 脱敏**（tailscale status --json / headscale nodes list 含节点公钥/密钥指纹，日志与入库前过滤）；同步调用 to_thread；独立 try/except |
| **aggregator** | 汇总最新结果 → 内存快照；写 samples（指标白名单）；派生指标 + 阈值判定 | 30s 内 API 读一致快照；**ping 超时语义**：在线但超时=warn 防抖（连续 3 轮）、离线=展示不告警 |
| **api** | 只读路由；手动 ping 限流（5s/设备） | 除 /api/ingest 外无写端点；统一 `{ok, data, ts}` |
| **web** | 静态单页 + Chart.js | 轮询刷新；状态灯绿/黄/红 |

### 3.4 API 设计

| 端点 | 方法 | 说明 | 响应要点 |
|---|---|---|---|
| `/api/overview` | GET | 聚合总览（主轮询点） | frp 隧道数/在线数、ts 设备数/在线数、derp 状态、云健康摘要、证书到期 Top、告警数 |

| `/api/frp` | GET | frps 隧道 + 链路质量 | 名称/类型/远程端口/状态/出入流量/**latency_ms/packet_loss**/更新时间 |

### 3.5 数据模型（SQLite）

```sql
CREATE TABLE monitor_nodes (
  id          TEXT PRIMARY KEY,      -- 'cloud-1', 'cloud-2'
  name        TEXT NOT NULL,
  role        TEXT DEFAULT 'primary',-- 'primary' | 'fallback'
  public_ip   TEXT,
  enabled     INTEGER DEFAULT 1,
  last_seen_ts REAL
);

CREATE TABLE devices (
  node_id      TEXT NOT NULL,
  device_id    TEXT NOT NULL,        -- tailscale 稳定 ID
  name         TEXT,                 -- HostName（显示名）
  tailscale_ip TEXT,
  os           TEXT,
  online       INTEGER,
  relay        TEXT,                 -- 'direct' 或 DERP region code
  last_seen_ts REAL,
  rx_bytes     INTEGER,
  tx_bytes     INTEGER,
  updated_ts   REAL,
  PRIMARY KEY (node_id, device_id)
);

CREATE TABLE tunnels (
  node_id       TEXT NOT NULL,
  tunnel_id     TEXT NOT NULL,       -- frps proxy name
  type          TEXT,                -- tcp/udp/http/https
  remote_port   INTEGER,
  local_addr    TEXT,
  status        TEXT,                -- running/offline
  traffic_in    INTEGER,
  traffic_out   INTEGER,
  updated_ts    REAL,
  PRIMARY KEY (node_id, tunnel_id)
);

CREATE TABLE samples (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  node_id      TEXT NOT NULL,
  metric_group TEXT NOT NULL,        -- frp_traffic|frp_link|ts_latency|system|network|cert_days|headscale
  metric_name  TEXT NOT NULL,        -- 白名单枚举（constants.py 校验）
  value        REAL NOT NULL,
  ts           REAL NOT NULL
);
CREATE INDEX idx_samples_lookup ON samples(metric_group, metric_name, ts);

CREATE TABLE alerts (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  ts       REAL NOT NULL,
  level    TEXT NOT NULL,            -- info|warn|crit
  source   TEXT NOT NULL,
  message  TEXT NOT NULL,
  resolved INTEGER DEFAULT 0
);
```

**v1.1 补充**：
- `metric_name` 走 constants.py 枚举白名单，insert 校验。
- frps 流量计数重启归零（E17）：samples 存原始值，aggregator 检测重置（当前值 < 上次值 → 标记 reset）；前端对骤降画虚线提示；后端 delta 计算二期。
- 8899 历史上限 14 天/500 点（E18）：**frp 链路质量长周期趋势由新面板自采**（F1 上线即自采 latency/packet_loss 入 samples），不依赖 8899 历史。

**清理策略**：samples 30 天（每小时删 + wal_checkpoint）；alerts 90 天；devices/tunnels 只留最新。

**阈值默认值**（config.py）：ts 延迟 >200ms warn / >500ms crit；丢包 >2%/5%；证书 <30d/<7d；磁盘 >85%/92%；frp 隧道离线即 warn；**ping 超时：在线但超时 → warn（连续 3 轮防抖），离线 → 展示不告警**。

## 4. 与现有 8899 frp 面板整合策略

**结论（维持 v1.0）：推荐「并列共存 + 只读消费」，可选「新面板反代旧面板入口」。**

| 方案 | 成本/风险 | 结论 |
|---|---|---|
| A. 迁移合并 | 高：agent 上报协议是在跑客户端契约，迁移须改所有客户端端点；电源控制不在新面板范围 | ✗ |
| **B. 并列共存 + 只读消费** | 零迁移；职责清晰（8899=设备 agent 链路+电源控制，新面板=基础设施+链路统一视图）；**双源冗余**（frps dashboard 权威隧道数据 + 8899 agent 链路质量，任一挂掉仍有另一半） | ✅ |
| C. 新面板反代旧面板 | 一个 nginx location（`monitor.dc-sy.cn/legacy/` → 8899） | 可选（二期） |

**v1.1 补充（评审 C3/E2）**：
- 消费 8899 `/api/status` 需其 **API_TOKEN 存入新面板 config**（env 注入 + 600 权限，见 §6 与 §8 E6）。
- **8899 既有公网暴露风险不在本方案内修复**：`0.0.0.0:8899` 公网可直连 + `GET /` 无鉴权（设备名/状态暴露面）。**排期 M5 前置任务（需用户审批）**：改绑 127.0.0.1 + nginx Basic Auth + token 改 header（与采集端契约无影响，风险低）；本期至少确认安全组对 8899 有访问限制并告知用户。

3. **cloud 上传**：首次 `git clone` 到 `/opt/monitor-panel/`；后续 rsync（exclude .git/venv/.env）。

   - **推荐：专用用户 `monitor` + sudoers NOPASSWD 白名单**（不复制 8899 的 root 运行模式——Web 服务 root 运行把攻破面放大到整机）：
     ```
     # /etc/sudoers.d/monitor-panel
     monitor ALL=(root) NOPASSWD: /usr/bin/tailscale status --json, \
       /usr/bin/tailscale ping *, \
       /usr/bin/headscale nodes list -o json, \
       /bin/ping -c 4 *, /usr/bin/openssl x509 -in /etc/letsencrypt/live/*/cert.pem -noout -enddate
     ```
     - **参数校验防注入**：tailscale ping 目标在 Python 侧正则校验（`^[0-9a-fA-F:.\-]+$`，仅 IP/主机名字符），exec 走参数列表不走 shell。
     - ICMP 权限依赖：F7 出站 ping 经白名单 `/bin/ping`（cap_net_raw 由 ping 的 setuid 或 sudo 承担）；headscale CLI 读 `/var/lib/headscale` 由 sudo 规避；`/etc/letsencrypt/live` 700 目录读由白名单 openssl 命令规避。
     - `tailscaled.sock` 权限实测 666，若实测 `tailscale status` 无需 sudo 则可免白名单该项（以实测为准）。
   - **若开发期坚持 root**：README 记录权衡（Web 攻破面=整机），**排期 M5 收敛为 monitor 用户 + 白名单**。
   - systemd 单元：`User=monitor`、`ExecStart` 指向 `current`、`Restart=on-failure` + **`StartLimitIntervalSec=300` / `StartLimitBurst=5` 防重启风暴（评审 C4/E15）**；日志 journald。
7. **nginx**：`setup_nginx_cert.sh` 生成 server block → 127.0.0.1:8898（标准反代头 + **Basic Auth 默认开启**，htpasswd 由脚本生成，`nginx -t && reload`）。
8. **预检 8a（评审 C1 阻塞项，新增）**：DNS 生效后从**外部网络**（无代理视角）执行：
   ```
   curl -sI --max-time 10 http://monitor.dc-sy.cn/.well-known/acme-challenge/probe
   ```
   - 404/200（nginx 正常）→ 走 http 通道；302 到 webblock.tencentyun.com / qcloud 拦截页 → 走 dns 通道。
   - 结合步骤 0 的备案确认结果，确定 `--issuance` 参数。
9. **证书签发（评审 C1，v1.1 双通道）**：
   ```
   scripts/setup_nginx_cert.sh --issuance http   # certbot --nginx -d monitor.dc-sy.cn（HTTP-01）
   scripts/setup_nginx_cert.sh --issuance dns    # acme.sh --issue --dns dns_ali -d monitor.dc-sy.cn（阿里云 AK，推荐兜底）
   ```
   - dns 通道：Ali_Key/Ali_Secret 注入（RAM 子账号，仅 DNS 解析读写权限），凭据文件 600 不入 git。
   - 不动现有 dc-sy.cn / headscale 证书与续期任务。
10. **续期配置（评审 C1 要求，新增）**：与签发方式一致——http 通道沿用 certbot timer；dns 通道配置 acme.sh `--cron` 自动续期（复用同一凭据）+ 续期后 reload nginx（install-cert/--reloadcmd）。上线 checklist 验证续期 dry-run。

## 7. 多云兜底 / 双公网 IP 扩展设计（二期路径）

**场景**：接入 cloud-2（公网 IP 2.2.2.2），实现"cloud 挂了由 cloud-2 兜底""双公网 IP 互检"。

**节点接入三步**：
1. cloud-2 部署轻量 agent（同一仓库：collectors + `POST /api/ingest`，Bearer token）。
2. cloud 主面板 `monitor_nodes` 加 `('cloud-2','fallback','2.2.2.2')`；samples/devices/tunnels 按 node_id 自动分区。
3. `config.probes` 加探测对（cloud-1→2.2.2.2 与 cloud-2→124.221.190.237 对等互检）。

**v1.1 补充（评审 E10，ingest 可达性——v1.0 设计盲点）**：
> 服务仅监听 127.0.0.1，远端 cloud-2 agent **无法直连 8898**。二期必须：
> - nginx 增加**单独 location**：`location = /api/ingest { proxy_pass 127.0.0.1:8898; }`（仅该路径公网可达，其余路径保持 Basic Auth）。
> - **双重鉴权**：该 location 关闭 Basic Auth 或保留 + 应用层 **Bearer token** 校验（agent 持有独立 token），防止公网任意写入。
> - 本期架构图与文档**明确标注 ingest 为"待二期定义"**，避免误导；/api/ingest 代码本期实现但默认禁用（404），二期随 location 一起启用。

**双公网 IP 互检逻辑**：两节点对等探测彼此公网 IP，面板按"探测视角"并列展示；失联时一眼定位"对端挂了 vs 我方出口挂了"。兜底只做监控与告警，**不做自动 DNS 切换**（避免复杂性，二期再议）。

**tailscale 侧**：headscale 支持多 DERP region；cloud-2 可作额外 exit node/中继；面板 relay 字段天然支持多 DERP 展示。
